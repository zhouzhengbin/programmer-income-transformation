## 1. NFR·体积预算：单文件 ≤ 800 行 / 60KB，超了先按职责拆模块

按「引擎核心 / 角色与绘制 / 关卡数据 / 场景与流程 / 入口装配」拆，不要先堆成单体再被体积闸门打回返工。

## 2. NFR·自包含可打开：零构建、无 CDN 外链，双击 index.html 就能玩

不依赖任何**运行时**外部资源与服务器；音效/图形全部本地生成或用相对路径资源。现成的动画/物理/缓动库**可以用**，但必须下载进 vendor/ 本地引用或内联，不许留 https:// 外链。「零依赖」= 断网也能开箱即玩，**不等于必须手搓一切**。

## 3. NFR·复用优先：粒子/缓动/物理/音效优先用成熟库，别闭门手搓

手搓既慢又不如成熟库精细；把库文件下载进 vendor/ 再引用，或内联核心实现并注明来源。

## 4. NFR·首屏完整：开始页的角色与主视觉必须真实绘制出来

开始页的 Canvas 角色（如主角/引导精灵）必须在 init 流程里启动绘制循环；只留 CSS 标题和按钮会让人以为页面渲染不全。

## 5. NFR·渐进加载：入口只做装配，场景模块按需载入

入口负责加载与调度，各关卡/场景模块按需载入，避免首屏被整包阻塞。

## 6. NFR·交付可打开：交付目录里必须有能直接玩的游戏主体

交付包要包含 index.html 与全部模块文件，并保证双击即玩；只有 report.md/manifest.json 视为交付失败。

## 7. NFR·运行期自检：真实浏览器里无报错、能开局、主循环在跑

断言：无 console error、开始页元素已渲染、点击开始能进入关卡、Canvas 帧在刷新。
