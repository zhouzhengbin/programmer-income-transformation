08. 为什么传统爬虫技术到这里就死了？

以前做爬虫的人，抓回数据后，通常用“正则表达式（Regex）”去匹配关键字（比如提取含有“buy”或者“comprar”的帖子）。但在真实的跨国商业环境中，这种做法完全失效：

RPA抓取的真实原始贴 (西班牙语) 传统关键字规则匹配结果 大模型 (LLM) 降维分析结果
"Hola, alguien tiene tubo de pvc de 4 pulgadas? necesito un chingo para una obra en Monterrey. DM porfa."
(包含拼写错误和墨西哥粗口俚语"un chingo")		 ❌ 忽略。没有标准采购词汇，无法识别"tubo de pvc"与"un chingo"的关联。 ✅ 极高意向客户。识别出产品：4英寸PVC管。地点：蒙特雷。意图：工程急需大量。
"Compro oro y plata al mejor precio, envíos a todo el país!" ✅ 识别为采购（包含 Compro/买）。 ❌ 打标签为：垃圾广告。这是回收金银的广告，不是我们要找的五金买家。
核心结论： 我们必须把死板的“数据表”，变成可思考的“工作流”。让AI充当一个懂100国语言、有10年外贸经验的资深业务员，帮我们逐条审核数据。

09. 在 Coze / Dify 中搭建数据清洗流水线

如果你是国内用户，推荐使用 Coze (扣子) ；如果需要更强的数据隐私，推荐开源的 Dify。以下以极易上手的 Coze 工作流为例：

1 创建智能体与工作流 (Workflow)
  1. 登录 coze.cn，点击左侧【工作空间】 -> 【创建工作流】。命名为：“跨国询盘自动提纯流”。
  2. 在画布中，你会看到一个 Start (开始) 节点。点击它，添加一个参数，命名为 raw_text，类型选择 String (文本)。这代表接收RPA抓取的一条帖子内容。
  3. 点击Start节点右侧的加号 +，添加一个 大模型 (LLM) 节点。
2 选择“智商”最高的大模型基座

清洗数据不仅需要翻译，更需要极强的“逻辑推理”和“意图剥离”能力。不要选那些便宜但愚蠢的轻量模型。

  • 推荐配置： 在 LLM 节点中，模型切换为 DeepSeek-R1、Gemini 1.5 Pro 或 Kimi (Moonshot 128k)。
  • 温度值 (Temperature)： 调到极低的 0.1 或 0.2。我们需要AI极其严谨、铁面无私地提取事实，绝不需要它在此刻发挥创意乱编造。
3 强制结构化输出 (JSON 节点)

如果AI只是输出一段中文回复（比如：“这个人想买水管”），我们的RPA依然无法把数据填回Excel的对应列中。我们必须让AI输出 JSON格式 的数据。

  1. 在 LLM 节点的输出设置中，勾选 JSON Mode（强制JSON输出）。
  2. 在 LLM 节点后，再添加一个 End (结束) 节点。
  3. 将 End 节点的输出类型也设置为 JSON，用于返回给影刀RPA。

10. 核心科技：价值万元的神级提词 (Prompt)

这个提示词经过了上千次外贸数据的实战测试，能够完美规避大模型的“幻觉”，精准剥离客户意图。请直接将其复制并粘贴到 Coze 的 LLM 节点“提示词”框内。

System Prompt - Data_Alchemist_v3.0
# Role (角色设定) 你是一个精通全球语言（特别是各地区民间俚语和方言）、且拥有20年B2B国际贸易经验的资深情报分析官。你的任务是分析从社交媒体抓取的原始多语种文本，剥离噪音，提取真实的采购商机。 # Input (输入) 原始文本内容：{{raw_text}} # Workflow (工作流与判断逻辑) 请对上面的文本执行极其严格的审查： 1. 语种识别： 识别文本使用的语言。 2. 意图判定 (最关键)： - 对方是否表现出“想要购买、正在寻找供应商、求购某物”的意图？ - 如果是自我推销、发广告、找工作、纯闲聊、或者卖东西，一律判定为"false" (无意向)。 - 即使对方用了很不正式的俚语（如西语的ocupo, chingo, lana等），只要核心意图是“要买”，即判定为"true" (有意向)。 3. 关键信息提取： 如果意图为true，请仔细提取： - Product (他想买什么具体产品？必须翻译为准确的中文商品名，如“十字槽沉头螺钉”，而不是“螺丝”)。 - Quantity (他想买多少？如果没有提及，输出"未知")。 - Contact (文本中是否包含电话、WhatsApp、邮箱？如果没有，输出"未提供")。 # Output Format (强制输出格式) 你必须严格按照以下 JSON 格式输出，不要包含任何 Markdown 标记或多余的解释文字，确保系统可以直接解析： { "is_buyer": true/false, "language": "识别出的外语", "reason": "用中文简短解释为什么判定他是/不是买家", "product_cn": "准确的中文商品名称", "quantity": "数量描述", "contact_info": "提取出的联系方式" }
避坑指南： 在Prompt的 {{raw_text}} 位置，你必须在工作流配置中，将其映射链接到 Start节点 的 raw_text 变量上。这样，每次传进来的新帖子，才会自动替换到这里进行分析。

11. 大闭环：将 RPA 与 AI 接口联通

现在，我们有一个抓取数据的 RPA 机器人，还有一个负责清洗数据的 Coze 智能体。怎么把它们连起来？这需要用到 API（应用程序接口） 或 Webhook。

实操：让影刀自动呼叫 Coze
  1. 在 Coze 工作流的右上角，点击 “发布为 API / Webhook”，你会获得一个专属的 URL 地址（你的API接口）和一串 Bearer Token（你的通信密码）。
  2. 回到 影刀RPA。打开我们在上一章写的流程，在“循环抓取数据”的内部，添加一个新指令：“发送 HTTP 请求”。
  3. 将请求方式设置为 POST，填入 Coze 的 URL。
  4. 在请求头（Headers）中，填入 Authorization: Bearer 你的Token。
  5. 在请求体（Body）中，将抓取到的那一条 Facebook 帖子内容（即 raw_text 变量）以 JSON 格式发送过去。
  6. 影刀会立刻收到 Coze 返回的 JSON 结果。

神迹发生：

你在影刀中再加一个 If 判断指令：如果返回结果里的 is_buyer == true，就把这个老外的名字、联系方式和翻译好的中文产品名，写入到一个名为《高意向黄金买家库.xlsx》的新表中；如果为 false，直接丢弃。
